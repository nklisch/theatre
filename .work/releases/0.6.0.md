# Theatre 0.6.0

Agents can switch Stage between Godot projects without restarting their MCP
session, and inspect disabled physics areas without producing engine errors.

## Delivered outcomes

- **switch-stage-project-within-mcp-session:** `project_select` selects one project
  explicitly and discards watches, baselines, spatial indexes, session overrides
  and cached clip location, including when selecting the same project. It loads
  the new defaults and returns selected path/port separately from verified runtime
  identity and readiness. Invalid inputs preserve the previous selection;
  unavailable targets remain selected and retry without fallback. Whole MCP calls
  drain before old connection teardown completes, and an accepted transition
  finishes even if its requesting call is cancelled. Tool descriptions, response
  messages and distributed agent guidance explain the fresh-snapshot requirement.
- **stage-inspects-disabled-area-monitoring:** Area2D/Area3D child inspection and
  the 3D containing-area scan check monitoring before querying overlaps. Disabled
  overlap data is null, not an observed empty list. Inspection never enables
  monitoring, and traversal continues below disabled areas.

## Operating boundary

Director continues to select `project_path` per call. Stage selection does not
start or stop games, delete saved recordings, restore previous sessions, discover
ports automatically, or change the external client feedback hook's environment.
Its explicit port overrides the selected project's TOML port; absent both it uses
9077 rather than retaining the old target's startup port. Existing MCP processes
must restart once to load this release; subsequent target changes use the tool.
Deploy the matching addon and restart affected Godot processes to load the
monitoring correction. Godot 4.7 remains the extension API target.
