## Responsive capture

Delivered outcome: `responsive-dashcam-capture`.

Spatial only disables new images without removing retained screenshots or changing recording intent. Automatic capture uses asynchronous OpenGL readback on a supported Compatibility renderer. GPU downsampling reuses the existing viewport rather than rendering the scene again. Capacity checks skip work before expensive capture, and saved clips report unfinished images as gaps.

Other renderers report automatic image capture unavailable while spatial recording continues. Explicit synchronous recovery remains available and can stall gameplay. A Forward+ engine journey verified that recovery path. Collection also reduces property-filtering overhead while preserving live exported-state behavior.

In bounded Voxlar idle-scene measurements, Lightweight render-pacing p95 fell from 63.744 to 42.537 ms. Measured image work fell from 6.993 to 0.855 ms. These Linux/Godot 4.7.1 Compatibility samples used a release Stage extension and debug consumer extension. They are not full-game benchmarks or a universal frame-time budget. The user reports substantially improved usability, but recording overhead remains material.

## Compatibility and operational limits

- The extension targets Godot 4.7. Install and deploy matched binaries and addons, then restart affected Godot and MCP processes.
- Recording remains enabled by default globally. Explicit project startup settings, including the consumer project's disabled setting, remain preserved.
- Automatic asynchronous capture is Compatibility/OpenGL-only. Unsupported visual capture does not disable spatial observation or recording.
- The intermittent native AccessKit editor undo crash remains unresolved. A passing final Linux gate does not establish its repair.
- Claude host-hook execution remains unverified. Native package validation and installation do not establish authenticated discovery or hook execution.
