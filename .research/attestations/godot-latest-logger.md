The fetched official Godot 4.5 documentation describes the custom-logger API. The fetched current stable documentation is Godot 4.7 and retains the same public `Logger` callback signatures and error categories. This is API evidence only; it does not select a Theatre binding or a minimum supported engine version.

## Attested details

1. Godot 4.5 documents `Logger` as a `RefCounted` custom receiver for the internal error/warning stream. A logger is registered using `OS.add_logger()`, which is documented as intercepting the internal message stream; `OS.remove_logger()` removes a previously added logger. [Logger description](https://docs.godotengine.org/en/4.5/classes/class_logger.html#description); [OS.add_logger](https://docs.godotengine.org/en/4.5/classes/class_os.html#class-os-method-add-logger); [OS.remove_logger](https://docs.godotengine.org/en/4.5/classes/class_os.html#class-os-method-remove-logger)
2. `Logger._log_error()` receives structured origin information: `function`, `file`, and `line`, plus either `code` or `rationale`, `editor_notify`, an error type, and `Array[ScriptBacktrace]`. The documented error categories are error, warning, script error, and shader error. [Godot 4.5 `_log_error`](https://docs.godotengine.org/en/4.5/classes/class_logger.html#class-logger-private-method-log-error); [Godot 4.5 `ErrorType`](https://docs.godotengine.org/en/4.5/classes/class_logger.html#enum-logger-errortype)
3. `Logger._log_message(message, error)` separately receives logged messages; its `error` flag identifies a message intended for stderr. The 4.5 logging guide makes the boundary explicit: `_log_message()` is not called for `push_error()` and `push_warning()`, even though those messages print to stderr. [Godot 4.5 `_log_message`](https://docs.godotengine.org/en/4.5/classes/class_logger.html#class-logger-private-method-log-message); [Godot 4.5 custom logger example](https://docs.godotengine.org/en/4.5/tutorials/scripting/logging.html#creating-custom-loggers)
4. Both callbacks may be invoked from multiple threads. The 4.5 API reference says an implementation may need locking; the logging guide’s example specifically calls out concurrent non-main-thread calls and a `Mutex`. [Godot 4.5 `_log_error` threading warning](https://docs.godotengine.org/en/4.5/classes/class_logger.html#class-logger-private-method-log-error); [Godot 4.5 `_log_message` threading warning](https://docs.godotengine.org/en/4.5/classes/class_logger.html#class-logger-private-method-log-message); [Godot 4.5 custom logger example](https://docs.godotengine.org/en/4.5/tutorials/scripting/logging.html#creating-custom-loggers)
5. Calling `print()`-family APIs from `_log_message()` or `push_error()`/`push_warning()` from `_log_error()` is not an effective way to emit another logged event: the 4.5 guide documents the engine’s recursion protection, and current stable documentation states the calls are unsupported and their resulting messages are console-only. [Godot 4.5 recursion note](https://docs.godotengine.org/en/4.5/tutorials/scripting/logging.html#creating-custom-loggers); [Godot 4.7 `_log_error` note](https://docs.godotengine.org/en/stable/classes/class_logger.html#class-logger-private-method-log-error); [Godot 4.7 `_log_message` note](https://docs.godotengine.org/en/stable/classes/class_logger.html#class-logger-private-method-log-message)
6. Since Godot 4.5, GDScript errors log a backtrace in the editor and debug exports by default. Release exports omit those backtraces by default for performance; enabling `debug/settings/gdscript/always_track_call_stacks` enables them. The logger reference further says callback-supplied backtraces do not include captured variables, and that capture from inside the callback is required to request them. [Godot 4.5 script-backtrace policy](https://docs.godotengine.org/en/4.5/tutorials/scripting/logging.html#script-backtraces); [Godot 4.5 Logger backtrace note](https://docs.godotengine.org/en/4.5/classes/class_logger.html#class-logger-private-method-log-error)
7. A `ScriptBacktrace` can be rendered with `format()` or inspected frame-by-frame with its count, file, function, and line methods. [Godot 4.5 `ScriptBacktrace`](https://docs.godotengine.org/en/4.5/classes/class_scriptbacktrace.html); [format](https://docs.godotengine.org/en/4.5/classes/class_scriptbacktrace.html#class-scriptbacktrace-method-format); [frame accessors](https://docs.godotengine.org/en/4.5/classes/class_scriptbacktrace.html#class-scriptbacktrace-method-get-frame-count)
8. The logging project settings can suppress what custom loggers receive: disabling stdout affects custom loggers, as does disabling stderr. [Godot 4.5 logging settings](https://docs.godotengine.org/en/4.5/tutorials/scripting/logging.html#project-settings)
9. Current stable (Godot 4.7) retains the same `Logger` error categories and the same `_log_error()` and `_log_message()` public signatures documented for 4.5. [Godot 4.7 Logger](https://docs.godotengine.org/en/stable/classes/class_logger.html); [Godot 4.5 Logger](https://docs.godotengine.org/en/4.5/classes/class_logger.html)

## Bounded current-run caveat

The public API establishes a current-process callback surface, but not universal historical capture: registration begins only after the logger is added. The 4.5 guide recommends registering in `_init()` to make registration as early as possible and explicitly says engine initialization messages remain inaccessible. [Godot 4.5 custom logger initialization guidance](https://docs.godotengine.org/en/4.5/tutorials/scripting/logging.html#creating-custom-loggers)
