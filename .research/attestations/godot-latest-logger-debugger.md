The fetched official sources define the editor-debugger extension surface and qualify a Logger delivery edge case. This is not a binding, product, or version decision.

## Attested details

1. `EditorDebuggerSession` is an editor-side object that cannot be instantiated directly; an `EditorDebuggerPlugin` supplies it. The documented session operations are debugger-panel tabs, messages to the attached remote instance, breakpoint management, profiler control, and active/debuggable/breaked state. [EditorDebuggerSession description](https://docs.godotengine.org/en/stable/classes/class_editordebuggersession.html#description); [methods](https://docs.godotengine.org/en/stable/classes/class_editordebuggersession.html#methods)
2. The documented `EditorDebuggerSession` signals are lifecycle and breakpoint-loop signals: `started`, `stopped`, `breaked`, and `continued`. The API reference does not list a structured engine-error or logged-message signal. This is an observation bounded to its documented public signal list, not a claim about internal editor implementation. [EditorDebuggerSession signals](https://docs.godotengine.org/en/stable/classes/class_editordebuggersession.html#signals)
3. `EditorDebuggerPlugin` is added by `EditorPlugin.add_debugger_plugin()`. It receives namespaced messages in `_capture()` after opting into a prefix through `_has_capture()`, and its example pairs this with `EngineDebugger` messages emitted by the running project. [EditorDebuggerPlugin description and example](https://docs.godotengine.org/en/stable/classes/class_editordebuggerplugin.html#description); [`_capture`](https://docs.godotengine.org/en/stable/classes/class_editordebuggerplugin.html#class-editordebuggerplugin-private-method-capture); [`_has_capture`](https://docs.godotengine.org/en/stable/classes/class_editordebuggerplugin.html#class-editordebuggerplugin-private-method-has-capture)
4. An editor debugger session can observe whether an attached remote instance has entered or exited the debug loop through `breaked` and `continued`; the break signal exposes whether the remote instance can enter that loop. These signals carry no structured error fields. [breaked](https://docs.godotengine.org/en/stable/classes/class_editordebuggersession.html#class-editordebuggersession-signal-breaked); [continued](https://docs.godotengine.org/en/stable/classes/class_editordebuggersession.html#class-editordebuggersession-signal-continued)
5. A Godot issue and its merged fix record a pre-fix delivery gap: when the built-in debugger broke on a script error, the error was not emitted to `Logger`. The fix states that errors are emitted in that case and that their reported location changes to the actual script location. The pull request was merged on 2025-06-24; this attestation does not infer which released stable tag first contains the merge without tag-specific evidence. [Godot issue #107662](https://github.com/godotengine/godot/issues/107662); [merged PR #107663](https://github.com/godotengine/godot/pull/107663)
6. The fetched 4.5-stable and 4.7.2-stable `Logger` source headers declare the same core `log_error` payload—function, file, line, code, rationale, editor notification, error type, and script backtraces—and the corresponding source applies the global stdout/stderr enablement checks before dispatch. [Godot 4.5 `logger.h`](https://raw.githubusercontent.com/godotengine/godot/4.5-stable/core/io/logger.h); [Godot 4.5 `logger.cpp`](https://raw.githubusercontent.com/godotengine/godot/4.5-stable/core/io/logger.cpp); [Godot 4.7.2 `logger.h`](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/core/io/logger.h); [Godot 4.7.2 `logger.cpp`](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/core/io/logger.cpp)

## Bounded comparison

For actionable structured diagnostics produced by the running engine, the documented `Logger` callback contains origin, category, rationale/code, and optional script-backtrace fields. The documented editor debugger extension API instead exposes debugger-session state and explicitly namespaced project/editor messages; it does not document a generic error-event callback. This comparison is confined to the cited public APIs.
